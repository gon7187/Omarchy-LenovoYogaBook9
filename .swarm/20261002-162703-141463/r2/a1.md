# Round 2 — agent a1

Both round-1 answers agree on the core design: drop keep-open and set `Speaker Force Firmware Load` before the PCM opens. Nothing was changed on the machine; I ran no new measurements this round, and the design is untested.

## REFUTED

- **README: "toggling `Speaker Config Id` 1 then 0 forces a reload"** → `tasdevice_config_put()` (`tas2781_hda.c`) only stores `tas_priv->cur_conf` and writes no hardware. I read this in the v7.2 source; a2 confirmed it by disassembling the installed 7.2.5 module. The toggle only works if a PCM OPEN happens while the value is 1 and another after it returns to 0.
- **"The 0.65 W is the amps idling"** → the datasheet (§6.5, p. 9–10) gives AVDD 15.5 mA at 1.8 V, PVDDL about 2.2 mA at 3.8 V and PVDDH 0.04–3 mA. That is 37–65 mW per amp, so 0.07–0.15 W for the pair at 8–12 V. At least 0.5 W is elsewhere.
- **a2: split the cost with RAPL and `turbostat`** → a2 itself reports that `energy_uj` was denied, and `turbostat` needs root. Without sudo, only battery `power_now`, the `runtime_status` files, the PCM `status` file and `low_power_idle_cpu_residency_us` are readable.
- **a2: a startup hook must hold back the speaker path until the flag is set** → not needed. After boot, `tasdevice_dspfw_init` leaves the per-device `cur_conf` at −1, so the first OPEN loads the calibration with or without the flag. The flag only has to be set before the second OPEN.
- **a2: `session.suspend-timeout-seconds = 3`** → too short if the reload really costs 2–3 s (linux-sound report, Yoga Pro 9 16IMH9, 2026-06-07). Every gap over 3 s would delay the next sound. Use 10–30 s.
- **A WirePlumber hook or `pactl`/`pw-mon` watcher reacting to "running"** → every amp kcontrol is consumed only inside the OPEN hook, so anything that fires on state change is too late. Both answers agree.

## CHANGED MY MIND

- **Verification.** I said the absence of `Unneeded loading dsp conf` proves calibration was written. a2 is right that it does not: `tasdev_load_calibrated_data()` has no success log and is inlined in the installed module. The check needs a kprobe or ftrace on the I2C bulk writes, plus an acoustic comparison.
- **udev rule.** I proposed removing `90-yoga-tas2781-no-runtime-pm.rules` together with keep-open. a2's staging is better: first prove reopen works with the rule in place, then test removing it separately.
- **`alsactl` restore.** I called it harmless. It can restore the flag to off, or restore a stale `Config Id`. The arming step must run after `alsa-restore`, and no intermediate `Config Id = 1` may ever be saved.

## UNRESOLVED

- **Why calibration is lost at all.** The datasheet says software shutdown retains registers (§8.5). Which block in Lenovo's firmware blob (shutdown or pre-power-up) clobbers the calibration registers is not decoded. The loss rests on the README's observation plus the skip-path in the code.
- **Why the PCM was `RUNNING` for about 32 minutes.** `/proc/asound/card0/pcm0p/sub0/status` showed `hw_ptr` advancing. If `yoga_dolby` or a stream feeding zeros keeps the sink running when idle, the suspend timer never fires and the design below does not close the PCM. Check with `pw-top` and `wpctl status` while idle.
- **Package C10.** `low_power_idle_cpu_residency_us` read 0 after two hours, but the PCM was running for part of that and the machine was busy. It is not proven whether C10 is reachable with the PCM closed.

## FINAL ANSWER

### 1. Where the 0.65 W goes

It is a mix, and the amps are the small part.

| Consumer | Estimate | Basis |
|---|---|---|
| Two TAS2781 idle | 0.07–0.15 W | Datasheet §6.5, extrapolated to 8–12 V PVDDH, including regulator loss |
| Two TAS2781 in software shutdown | about 40 µW | Datasheet §6.5 |
| SOF DSP, HDA link, ALC287 in D0, plus graph wakeups if the sink is running | at least 0.5 W | Remainder; not split |

Read-only split, on battery at fixed brightness, averaging `/sys/class/power_supply/BAT*/power_now` for 2–3 minutes per state:

| State | What is on | How it arises |
|---|---|---|
| S0 | Amps active, DSP suspended, PCM closed | Fresh boot before any sound (the udev rule blocks `tas2781_runtime_suspend`) |
| S1 | Everything off | After a PCM close |
| S2 | Amps, DSP and codec on, no wakeups | PCM open, sink paused |
| S3 | S2 plus graph wakeups | PCM running silence |

- S0 − S1 is the amps alone, S2 − S0 is DSP, link and codec, and S3 − S2 is PipeWire wakeups.
- Cross-check each state with `power/runtime_status` of `0000:00:1f.3` and `i2c-TIAS2781:00`, and the PCM `status` file.
- If the 8.93 W baseline was taken in S0, the whole 0.65 W is SoC-side.
- S2 and S3 only arise with the current keep-open config, so measure them before changing anything.

### 2. The calibration bug

It is still present in v7.2 and in master, and I found no fix commit. The histories of `sound/soc/codecs/tas2781-fmwlib.c` and `sound/hda/codecs/side-codecs/tas2781_hda_i2c.c` through August 2026 (f6635d6, 431c156, b601633) do not touch it. b601633 (TAS2563 invalid calibration) and b7e26c8 (ROG Ally) are unrelated.

- **OPEN:** `tas2781_hda_playback_hook` takes a runtime-PM reference and calls `tasdevice_tuning_switch(priv, 0)`, which calls `tasdevice_select_tuningprm_cfg()`.
- **Skip:** `tasdev_load_calibrated_data()` runs only when `tasdevice[i].cur_conf != cfg_no`. Otherwise it logs `Unneeded loading dsp conf` and writes nothing.
- **CLOSE:** the shutdown block runs and the reference is dropped; `cur_conf` is not invalidated.
- **History:** bec7760 (March 2024) removed the old `cur_*` reset in runtime suspend.

**Minimal userspace action:** set `Speaker Force Firmware Load` (numid=3) to on, **before** OPEN. The flag is persistent and is tested inside the OPEN hook. It forces `cur_conf = -1`, then reloads program, config and calibration. Set after OPEN, it only affects the next OPEN. Leave it on permanently rather than re-arming.

### 3. Amps off with the PCM alive

Not possible with the current driver, and it would save at most about 0.1 W.

- **Kcontrols:** none powers the amp. numid 7 and 9 are codec pin switches, and mute leaves the Class-D stage switching.
- **Runtime PM:** the reference is held from OPEN to CLOSE, so the amp cannot suspend under an open PCM.
- **Runtime resume:** `tas2781_runtime_resume` only calls `tasdevice_prmg_load(cur_prog)` and does not reload calibration. Only `tas2781_system_resume` resets `cur_*` and reloads everything.
- **Raw I2C writes:** would desynchronise the driver's cache; do not use them.
- **Noise gate:** about 15 mW per amp on silence, but it is set by the firmware blob with no control exposed.

### 4. Proposed logic

**Use option (d): a static flag plus WirePlumber's normal idle suspend.** The power sequencing is already event-driven inside the kernel's OPEN/CLOSE hook, so no watcher is needed.

1. Once per boot, after `alsa-restore` and after the control exists (it is created asynchronously after firmware load):
   ```bash
   # bin/yoga-amp-arm, from a user unit after wireplumber
   for _ in $(seq 50); do
     amixer -c0 -q cset name='Speaker Force Firmware Load' on 2>/dev/null && exit 0
     sleep 0.2
   done; exit 1
   ```
2. In `52-yoga-speakers-keep-open.conf`, change `session.suspend-timeout-seconds` from 0 to 10–30.
3. Keep the udev rule for now. Once reopen is proven, test removing it as a separate step.

| Option | Verdict |
|---|---|
| (a) WirePlumber Lua hook on node state | Fires after OPEN, too late for calibration |
| (b) `pactl subscribe` / `pw-mon` watcher | Same lateness, plus an extra process and reconnect races |
| (c) Suspend timeout per power source | Policy only; does not fix calibration. Optional later (0 on AC, 10–30 s on battery), but it needs a WirePlumber restart to switch |
| (d) Force flag + normal suspend | Recommended; reload is synchronous inside `open()` |
| Kernel patch: `cur_conf = -1` on CLOSE | The proper fix; reloads config and calibration without the program, so much cheaper. Worth sending to linux-sound |

**Failure modes:**

- **Start delay:** a full program reload on each OPEN, reported as 2–3 s on a sibling model. Short notification sounds arrive late.
- **Pop/click:** the datasheet lists 0.8 mV for shutdown transitions; a pop during program reload is possible and unmeasured.
- **Sink never idles:** if something keeps the sink running, the PCM never closes and nothing is saved.
- **I2C write failure mid-reload:** that OPEN plays untuned. Watch the kernel log for `process_block` and `bulk_wr` errors.
- **Flag lost:** it resets on boot or module reload, and `alsactl` restore may overwrite it; hence the arming unit.
- **Direct ALSA clients and other streams:** capture or another playback stream can hold the DSP in D0 regardless.

**Verification (needs root for the tracing steps):**

1. Enable dynamic debug: `module snd_soc_tas2781_fmwlib +p` and `module snd_hda_scodec_tas2781_i2c +p`.
2. With the flag off, a reopen should log `Unneeded loading dsp conf 0`. This reproduces the bug.
3. With the flag on, a reopen must not log it. Then confirm the writes with a kprobe or ftrace on the I2C bulk-write path for both amps.
4. Take the reload duration from the journal timestamps.
5. Record a sweep with the internal mic after boot and after a reopen, and compare the 100–300 Hz level. The sink monitor is digital and shows nothing.
6. When idle: PCM `status` reads `closed`, `0000:00:1f.3` is `suspended`, and battery power is back near 8.9 W.
7. Repeat across a short pause, a pause longer than the timeout, suspend/resume, a WirePlumber restart and a reboot.
