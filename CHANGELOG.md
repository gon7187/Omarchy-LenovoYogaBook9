# Изменения форка

## 2026-09-16 — лог смены языка панели

- Панель иногда сама уходит на английский, момент не поймать. `yoga-panel/backend.py`
  теперь пишет в журнал каждую смену системной раскладки: с какого устройства пришло
  событие, какое приложение было в фокусе (только класс окна, без заголовка), и
  каждое переключение самой панели. Нажатия не логируются.
- Смотреть: `journalctl --user -u yoga-panel -g 'yoga-panel:'`.
- Подозреваемые: `omarchy-system-lock` (блокировка по бездействию) делает
  `switchxkblayout all 0`; `hl-virtual-keyboard-fcitx5` — «главная» клавиатура, у fcitx5
  в профиле только `keyboard-us`, и он шлёт `English (US)` сразу после переключения на
  русский; перезапуск панели тоже сбросил раскладку на английский.

## 2026-09-16 — клавиатура экрана блокировки переживает обновления

- `bin/yoga-recovery snapshot` сохраняет pacman-хук, `TouchKeys.qml` и
  `zz-yoga-relogin.conf`; `check` (его зовёт post-update хук) ругается, если после
  обновления из `LockView.qml` пропала клавиатура.
- `yoga-lock-keyboard apply` падает с сообщением в выводе pacman, если Omarchy
  переделал `LockView.qml` и вставить клавиатуру не удалось.
- Блокировка при входе срабатывает только если клавиатура на месте — после
  неудачного обновления загрузка не упрётся в пароль, который нечем набрать.

## 2026-09-16 — пароль везде через экранную клавиатуру

- Вернул настоящий пароль на экране блокировки (`yoga-lock-nopass remove`): теперь
  его есть чем набрать.
- После загрузки сессия сразу блокируется (`config/hypr/autostart.lua` →
  `omarchy-system-sleep-lock 12000`, он повторяет попытку, пока шелл не поднимется).
  Автологин остаётся, но в систему пускает только экран с клавиатурой.
- `yoga-lock-keyboard install` дополнительно пишет `/etc/sddm.conf.d/zz-yoga-relogin.conf`
  (`Relogin=true`): после выхода из сеанса SDDM не показывает свой экран входа без
  клавиатуры, а снова входит автоматически — и сессия опять блокируется.
- Сон и гибернацию Omarchy уже блокирует сам (`omarchy-system-sleep-lock`).
- Не покрыто: если TPM не отдаст ключ диска (сброс/обновление прошивки, смена
  Secure Boot), LUKS-пароль спросят до загрузки системы, где сенсора нет — нужна
  USB-клавиатура.

## 2026-09-16 — экранная клавиатура на экране блокировки

- Диск открывается через TPM, вход — автологин, так что пароль спрашивает только
  экран блокировки Omarchy (после сна, гибернации, `omarchy system lock`). Он держит
  `ext-session-lock`, и Hyprland не показывает поверх него `yoga-panel` — ввести
  пароль было нечем.
- `config/omarchy/lock/TouchKeys.qml` — сенсорная клавиатура (буквы, Shift, цифры и
  символы, ⌫, ↵) внутри самой поверхности блокировки, только на нижнем экране `eDP-2`.
- `bin/yoga-lock-keyboard install` (нужен root через sudo/pkexec) кладёт её в
  `/usr/share/omarchy/shell/plugins/lock/`, вставляет в `LockView.qml` и ставит
  pacman-хук, который повторяет патч после каждого обновления пакета `omarchy`.
  `remove` откатывает. Изменения подхватываются после `omarchy-restart-shell`.

## 2026-09-16 — автояркость: ярче в комнате и плавнее

- Кривая `bin/yoga-autobrightness` теперь таблица опорных точек люкс → %
  (интерполяция по логарифму): `20:10, 30:25, 40:55, 60:65, 150:82, 600:100`.
  При обычном свете сенсор показывает 40–60 люкс — было 28–39%, стало ~55–65%.
  Темнота (≤20 люкс) без изменений — 10%. Кривую можно переопределить строкой
  `curve = …` в `~/.config/yoga-autobrightness.conf` без перезапуска.
- Яркость меняется не скачком, а шагами по 1% за ~0,7 с.
- Сенсор в спокойной комнате держит значение 20–60 с и прыгает на четверть
  (записано: 50 → 39 → 53 → 42 люкса). Показания сглаживаются в логарифме,
  порог 5%: на этой записи экран не дёргается ни разу (раньше — 6 раз за 3 минуты),
  включённый свет догоняет за ~15–25 с.
- OSD показывается один раз на весь плавный переход, а не на каждом шаге.
- Проверено: обратной связи от подсветки нет — при 10% и 100% яркости сенсор
  показывает одно и то же.

  Заставка через 150 с осталась.
- `systemctl --user mask --now omarchy-sleep-lock.service`: экран не запирается перед
  suspend/hibernate (по просьбе владельца). Idle-блокировка через 5 мин осталась

## 2026-09-16 — басы пропадали после перезапуска браузера

- Причина: при закрытии PCM драйвер TAS2781 гасит усилители, при открытии поднимает,
  но калибровку пишет только при смене конфигурации DSP. Закрыл браузер → через 5 с
  WirePlumber закрыл устройство → басов нет до ребута.
- `config/wireplumber/52-yoga-speakers-keep-open.conf`: динамики никогда не suspend'ятся,
  PCM остаётся открытым (проверено: IDLE вместо SUSPENDED, кодек active). Цена — батарея.
- Вернуть калибровку без ребута: переключить `Speaker Config Id` 1 → 0.

## 2026-09-16 — загрузка без пароля и засыпание усилителей

- `bin/yoga-tpm-unlock`: разблокировка LUKS через TPM2 без привязки к PCR (без Secure Boot,
  защита только от вынутого SSD — осознанный выбор). Добавляет слот TPM, пароль остаётся;
  initramfs переводится на systemd/sd-encrypt drop-in'ом `zz-sd-encrypt.conf`,
  `cryptdevice=` → `rd.luks.name=` в `/etc/default/limine` (копия `limine.yoga-before-tpm`).
  `remove` откатывает.
- `config/udev/90-yoga-tas2781-no-runtime-pm.rules`: усилители TAS2781 не уходят в runtime
  suspend. После пробуждения драйвер не перезаливает программу и калибровку, если номер
  программы не менялся, — звук был хорош после загрузки и портился после паузы.

## 2026-09-16 — звук: эквалайзер вместо нерабочего 4-канального режима

- Выяснено: на драйвере SOF PCM динамиков только 2 канала, 4-канальный синк из
  `51-yoga-bass-speakers.conf` не включался (`out of range:2-2`). В 2-канальном режиме
  кодек сам отдаёт поток на оба ЦАП, басовики звук получают. Файл отключён
  (перенесён в `~/.local/state/yoga-book/disabled/`).
- Установлен `62-yoga-dolby-eq.conf`: эквалайзер из драйвера Windows (верха смягчены)
  + полка 300 Гц, sink `yoga_dolby` по умолчанию.
- `yoga-volume`: подъём басов от +4 дБ на 100% до +12 дБ на 0% (было до +19 дБ — клиппинг).
- Найдено: калибровка усилителей TAS2781 в UEFI с нулевым CRC, ядро её отбрасывает.
- Замер: эквалайзер цифрово работает (+13 дБ на 100 Гц на выходе), но на слух басов нет
  ни с обработкой, ни без. `yoga-amp-calib fix` записал CRC в `CALI_DATA`
  (оригинал: `~/.local/state/yoga-book/CALI_DATA.orig`), эффект — после перезагрузки.
- **Результат: после перезагрузки ошибки калибровки нет, басы вернулись.** Причиной была
  именно отброшенная калибровка усилителей, а не маршрутизация и не эквалайзер.
